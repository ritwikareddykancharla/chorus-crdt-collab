01 · Problem

Problem

Treating an AI model as a real peer inside a shared engineering document exposes four distributed-state problems whenever humans and agents type at the same moment.

Multiplayer Human + AI Sync

Overview

ChorusCRDT implements a sequence Conflict-Free Replicated Data Type from scratch with deterministic conflict resolution and binary delta encoding. Every character carries an immutable (actor_id, lamport_clock) identifier alongside its causal left and right neighbors (origin_left and origin_right). Before Amazon Bedrock (us.amazon.nova-lite-v1:0) rewrites a selected paragraph, ChorusCRDT binds a RelativeRange to those item IDs so concurrent human edits above the paragraph shift the resolved offsets automatically without slicing characters. Peers reconcile offline or reordered edits using compact 18 B varint StateVector headers and run-length compressed binary deltas (150.0 B median wire exchange, 99.98% smaller than full CRDT JSON snapshots), persisted in SQLite WAL checkpoints.

01 · SHIFTING OFFSETS

Async AI Edits Land on Stale Indices

An LLM takes 400 to 700 ms to rewrite characters 210..340. If an engineer types 50 characters in Section 1 during that window, applying the response at raw integer offsets overwrites the wrong paragraph.

02 · SCRAMBLED WORDS

Concurrent Inserts Can Interleave

When two humans and an AI teammate insert text at the same boundary during a Wi-Fi blip, naive index merges interleave letters from separate words or diverge when network packets arrive out of order.

03 · SNAPSHOT BLOAT

Full JSON Re-Syncs Waste Bandwidth

Sending a full CRDT item array in JSON for a 10 KB document transmits nearly 2 MB of metadata per keystroke burst, breaking sub-50 ms sync budgets and inflating per-builder cloud costs.

04 · GLOBAL UNDO COLLISIONS

Linear Undo Erases Teammates' Work

In a multiplayer session, a global undo stack reverts whichever edit arrived last. Reverting an unhelpful AI rewrite 10 seconds later should never delete sentences a human teammate typed afterward.

03 · Implementation

Implementation

Four focused backend modules implement the Yata sequence CRDT, LEB128 varint wire encoding and SQLite compaction, randomized partition fuzzing, and live Amazon Bedrock co-authoring.

13 / 13 Unit Tests Passing
01 · YATA SEQUENCE CRDT & LOGICAL ANCHORS chorus_crdt/yata_engine.py
Every inserted character receives an immutable (actor_id, lamport_clock) address and stores the exact neighbors to its left and right when typed. Cursors and AI selections pin to those item IDs rather than integer positions so upstream edits never misalign an active rewrite.
YataDocument._integrate_ready_insert() enforces Yata's non-crossing origin rule with a fast O(1) adjacent-origin check (32.07 us per-character insert, 1.884 ms p50 remote span merge). Out-of-order network arrivals wait in _pending_inserts and _pending_mutations until causal origins arrive, while delete_version=(lamport, actor, deleted) guarantees commutative tombstone convergence.
02 · BINARY STATEVECTOR DELTA & SQLITE COMPACTION chorus_crdt/wire_sync.py
Instead of sending full JSON document copies on every edit or reconnect, peers advertise how many operations they have seen per author in an 18 B binary header and receive only the missing edits packed into run-length runs.
encode_state_vector() emits CHSV\x01 LEB128 varint maps, and encode_binary_delta() deduplicates actor and transaction IDs into a header string table before packing contiguous keystrokes into single OP_TAG_INSERT_RUN frames (150.0 B median wire exchange, 99.98% smaller than full CRDT JSON). SQLiteCRDTStore folds WAL frames into compacted binary checkpoints in 2.291 ms (p50).
03 · MULTI-PEER PARTITION & CHAOS FUZZER chorus_crdt/fuzzer.py
Distributed sequence CRDTs must converge not only on happy-path keystrokes, but also when collaborators split across offline Wi-Fi partitions, packets arrive backwards, duplicates replay, or dropped frames heal via delta sync.
run_convergence_fuzz_suite() executes 320 deterministic randomized seeds across 4 human and AI replicas (peer-maya, peer-alex, bedrock-nova, peer-sam), replaying 198,517 reordered packets, 20,317 duplicates, and 13,828 dropped packets healed via sync_peers_binary() with 320 / 320 (100.0%) convergence and 0 interleaved word corruptions.
04 · LIVE BEDROCK PEER & SELECTIVE CAUSAL UNDO chorus_crdt/ai_collaborator.py · server.py
@nova-editor joins the document as a named peer with its own replica, rewrites anchored sections via Amazon Bedrock while humans type concurrently, and records transaction item lists so any author's edit can be reverted independently.
coedit_document() forks concurrent replicas for peer-maya and bedrock-nova, calls us.amazon.nova-lite-v1:0 via the Bedrock Converse API (544.0 ms p50 across 12 runs), reconciles binary deltas, and powers undo_actor() to emit inverse tombstones and restores in 0.073 ms (p50) with 0 collateral characters lost.
04 · Trade-Offs

Trade-Offs

Every design choice in ChorusCRDT balances per-character metadata overhead, causal undo fidelity, and serverless unit economics.

Design Decisions
01 · CHARACTER ITEMS + WIRE RLE

In-Memory Item Granularity vs. Run-Length Wire Packing

Addressing individual characters in memory makes RelativeAnchor cursor pinning and non-interleaving conflict resolution exact at any character boundary, at the cost of higher Python object overhead than flat strings. Packing sequential runs into OP_TAG_INSERT_RUN records in wire_sync.py keeps network deltas at 150.0 B median and SQLite checkpoints within 1.02x of raw UTF-8 text size.

02 · RETAINED TOMBSTONES

Keeping Tombstones for Offline Peers & Selective Undo

Deleted characters stay in the sequence marked deleted=True rather than being immediately spliced out. Retaining tombstones adds small metadata to checkpoints, in exchange allowing offline collaborators whose origin_left references a deleted item to merge without orphans and letting undo_actor() restore replaced sentences cleanly.

03 · REQUEST-RESPONSE VS WEBSOCKETS

Serverless $0.00 Idle Lambda vs. Persistent Fan-Out

Deploying /api/* on on-demand AWS Lambda behind CloudFront keeps idle cost at $0.00/month while running the exact binary CHSV/CHDL protocol and live Amazon Bedrock calls. Scaling to hundreds of simultaneous sub-50 ms cursors on one hot doc pairs the same binary codec with WebSocket fan-out rooms backed by S3 checkpoint flushing.

04 · SCOPED SECTION REWRITES

Anchored Span Edits Instead of Whole-Document LLM Rewrites

Having Amazon Bedrock regenerate an entire 10 KB document takes seconds, burns thousands of tokens, and risks hallucinated edits in unrelated sections. Scoping @nova-editor to a pinned RelativeRange keeps median Bedrock latency at 544.0 ms (203.6 mean tokens) and confines tombstones strictly to the selected span.
